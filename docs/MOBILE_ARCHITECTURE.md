# Mobile Architecture & Platform Boundaries

## 1. Overview & Stack

The mobile companion application resides in `apps/mobile-companion/` and is built using:
- **Framework**: React Native with Expo 52+
- **Language**: TypeScript
- **Target Platforms**: Android (primary companion evidence collector) & iOS (dashboard and status viewer)

---

## 2. Platform Capability Boundaries

### Android Architecture:
- Android provides `android.service.notification.NotificationListenerService`, an official operating system API allowing user-authorized services to receive system-wide notifications.
- The companion app requests the `BIND_NOTIFICATION_LISTENER_SERVICE` permission.
- The merchant explicitly enables **Notification Access** for RGS Companion in system settings.
- The service monitors incoming notifications from supported Indian banking and UPI apps (e.g. PhonePe, Google Pay, Paytm, BHIM, HDFC, ICICI, SBI).
- **Offline Persistence**: In the event of network disruption, captured notifications are buffered locally in encrypted SQLite storage and batched to the API when network connectivity resumes.

### iOS Platform Boundaries (Strict Invariant):
> **IMPORTANT SECURITY & CAPABILITY BOUNDARY**:
> Apple iOS sandboxing explicitly forbids any third-party application from inspecting, reading, or intercepting notifications generated by other applications.
> There is **no public API** in iOS equivalent to Android's `NotificationListenerService`.
> 
> **RGS Ledger will NEVER implement or promise a fake iOS notification listener.**
> The iOS companion app functions strictly as a merchant dashboard viewer, allowing merchants to inspect payment status, generate manual QR codes, and monitor paired Android devices.

---

## 3. Device Pairing & Authentication

1. **Pairing Initiation**: The merchant generates a one-time 8-character pairing code on the Merchant Dashboard.
2. **Device Registration**: The companion app scans the pairing QR code or enters the code along with its unique hardware fingerprint.
3. **Mutual Token Exchange**: The API validates the pairing code, registers the device in `android_devices`, and issues a cryptographically signed device bearer token used for all subsequent evidence ingestion requests.
4. **Heartbeat Monitoring**: The device transmits a periodic heartbeat reporting battery status, notification listener activity, and local queue depth.
